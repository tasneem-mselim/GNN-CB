📖Overview

GNN-CB bridges two research directions: LLM code generation benchmarks and graph machine learning benchmarks. Unlike prior work, GNN-CB evaluates full repository-level GNN implementations — not isolated functions or fixed-model performance.

🎯 Near-Human on Easy Tasks

Frontier proprietary reasoning LLMs (Claude Opus 4.7, GPT-5.4 Codex) approach or match human top on well-templated GNN tasks — e.g., Claude Opus 4.7 reaches 0.998 on C08 Liar Nodes (Δ = +0.002 above human top).

📉 Substantial Gap on Hard Tasks

On Medium and Hard competitions, the strongest LLMs trail the best human submission by 0.05–0.40, particularly for tasks requiring domain-specific graph construction, temporal reasoning, or careful handling of class imbalance.

🔀 Consistency, Not Capability

Every evaluated model achieves at least one near-human peak score, yet none sustains that level on average. The Best–Mean gap ranges from 26 pp (frontier reasoning) to 44 pp (open-source chat models).

🤝 Model Complementarity

No single model dominates across all 18 competitions. Kimi k2.6 surpasses human top on C09 GraphFMD (+0.153); GPT-5.4 Codex leads on C13 GTA (+0.036). Ensembling or task-aware routing may be more effective than scaling a single model.

📊 Discriminating Signal

Competition-style, repository-grounded evaluation provides a more informative signal of end-to-end GNN coding ability than isolated-function benchmarks. Wide cross-task variance reveals systematic model weaknesses.

🔬 Living Benchmark

GNN-CB is released as a living benchmark with automated evaluation infrastructure, dynamic leaderboards, and reproducible execution pipelines — supporting continuous comparison of future models and serving as a progressive educational corpus.

⚙️Evaluation Protocols

Three complementary protocols ensure fair, reproducible, and directly comparable assessment of human and LLM submissions.

Protocol I

Competition Design

  • 18 independent GNN competitions
  • Standardized repositories and READMEs
  • Hidden test sets, never exposed
  • Automated GitHub Actions scoring
  • Encrypted submission mechanism
  • Live leaderboard updates
Protocol II

Human Evaluation

  • GNN-only architectures (no CNN/RNN)
  • 3 CPU hours per task budget
  • Fixed random seed (seed=25)
  • ≤5 hyperparameter tuning runs
  • 1 final submission per competition
  • LLM assistance: low-level only
Protocol III · Non-Agent

LLM Evaluation (API)

  • Frozen prompt template (no tuning)
  • 5-slot filling from repository
  • Plan-then-code paradigm
  • Bounded repair loop (k ≤ 5)
  • CPU-only execution sandbox
  • Zero-shot, temperature = 0
Protocol III · Agent

LLM Evaluation (Agent)

  • Autonomous repository exploration
  • Self-directed code generation
  • Iterative repair without human input
  • Same k ≤ 5 repair budget
  • Identical hidden-test pipeline
  • Claude Code / GPT-5.4 Codex modes
